# 发布说明

## v0.10.0（2026-09-15）

- **总结不再只看开头**：原来的「前 8,000 字符」取的是 PDF 文本的前 8,000 字——通常是标题、作者、摘要和引言开头，**不包含方法与结论正文**，因此长论文的「主要结论」经常是模型猜的。现在「生成总结」改为读取论文的**开头与结尾**（约 6,000 + 2,000 字，含摘要与结论），并在系统提示里说明「只提供了开头与结尾」，如需补读可自行按偏移读取全文。
- **新增「总结全文（分段精读）」**：把整篇正文按约 7,000 字切段（长文档在全文范围内均匀取样，**始终包含开头与最后一节**，最多 14 段），逐段压缩成带「背景／方法／结果／结论」标签的要点，再合并成最终的结构化总结。费用与耗时高于速览，由用户自己点。
- 总结会记录依据：界面显示「本次总结依据：开头与结尾节选（含摘要与结论）」或「全文分段精读（N 段）」，数据库新增 `summary_scope` 与 `summary_characters`，重新打开文献仍能看到上次用的是哪种方式。
- 摘要/引言的抓取按段落或句末断句，不会从半句中间切断；`POST /paper/summarize` 新增 `scope=excerpt|full` 参数（默认 `excerpt`，向后兼容）。

本次产物：`releases/ScholarMate_0.10.0_x64_zh-CN.msi`、`releases/ScholarMate-source-0.10.0.zip`，校验值见 `releases/SHA256SUMS.txt`。安装包未签名。

## v0.9.0（2026-09-15）

- **长回答不再被上限打断**：以前一旦单次回复撞到输出上限，就会报「回复达到 Token 上限，请缩小任务范围后重试。」并把已经生成的内容整段丢弃。现在会自动从中断处续写（最多 3 次，约 3 万 token），读者看到的是连贯的一篇回答；若仍未写完，回答末尾会加一句「回复「继续」即可接着写」，而不是失败。
- **输出上限提到模型允许的最大值**：`max_tokens` 从 4000（总结/翻译 2000）改为 8192，也就是 deepseek-chat / deepseek-reasoner 的单次输出上限。它只是上限而非目标，只有真正生成的 token 才计费，所以不会因此多花钱。
- 续写提示词明确要求「接着写、不要重复、不要重新开头」；续写也会保留工具调用轮次，所以「先读文献再写长文」这种回答同样能写完。
- 工具读取轮次从 12 提到 16，并把提示改成动作建议（「把问题拆小一点再问」）；单轮资料字符预算保持 15 万，因为模型上下文窗口是硬限制，超出会让整次请求失败。
- `POST /chat` 的结束帧新增 `truncated` 与 `continuations` 字段，界面据此显示提示；被截断的回答会带上可持久保存的说明，重新打开对话仍能看到。

本次产物：`releases/ScholarMate_0.9.0_x64_zh-CN.msi`、`releases/ScholarMate-source-0.9.0.zip`，校验值见 `releases/SHA256SUMS.txt`。安装包未签名。

## v0.8.0（2026-09-15）

- **多会话：聊乱了就新建一条**。学术对话从「一条无限延长的记录」改为多条独立对话：顶栏可**新建对话**、下拉切换、重命名、删除当前对话。每条对话只带回自己的历史给模型，互不污染；删除一条不影响其他对话与已上传的附件。首条消息会自动成为对话标题（之后可改），列表显示消息数与最近一次提问。
- **多画像：两个方向同时进行**。可以建立多个学术画像（名称 + 专业、领域、目标、时间等字段），侧边栏随时切换「当前画像」，设置页可新建、复制当前画像、编辑、删除（至少保留一个）。计划生成、总结、翻译等任务使用当前画像。
- **每条对话记住自己使用的画像**：新建对话默认取当前画像，之后即使把「当前画像」切到另一个方向，这条对话仍然用它自己的画像回答；也可以在对话顶栏直接为某条对话换画像。删除某个画像时，引用它的对话会自动改为使用当前画像，不会失效。
- **旧数据自动升级**：原来的单一画像会转成第一个画像（用研究领域命名，如「自然语言处理」），原来那条无限对话记录会归入「历史对话」，其余设置、附件、计划、文献都不变。
- 新增接口：`GET/POST /threads`、`GET/PUT/DELETE /threads/{id}`、`GET /threads/{id}/export`、`GET /profiles`、`POST /profiles`、`PUT/DELETE /profiles/{id}`、`POST /profiles/{id}/activate`。`POST /chat` 接受 `thread_id`，未提供时自动新建一条并在 SSE 结束帧返回该对话；`GET /status` 增加 `profile_id` / `profile_name` / `profile_count`。

Windows x64 MSI 可覆盖升级，保留数据库、凭据、附件与对话记录。本次产物：`releases/ScholarMate_0.8.0_x64_zh-CN.msi`、`releases/ScholarMate-source-0.8.0.zip`，校验值见 `releases/SHA256SUMS.txt`。安装包未签名。

## v0.7.0（2026-09-15）

- **对话可以上传文件**：输入框旁新增「上传文件」，也支持把文件拖进输入框、直接粘贴剪贴板里的图片。一条消息最多 8 个附件，单个不超过 20 MB。文件保存在数据目录的 `uploads/`，随数据目录一起迁移。
- **文档在本机读出文字再交给 AI**：Word（.docx）、Excel（.xlsx）、PowerPoint（.pptx）、PDF 与文本类（.txt/.md/.csv/.json/.html/.tex/.bib/.py/.log 等）在上传时本地解析为文字，随该条消息发送；超过 6,000 字的文档只发送开头，模型可用只读工具 `read_workspace` 的 `attachment` 动作按偏移读取全文。Excel 按工作表逐行输出、PPT 按幻灯片输出、Word 保留段落与制表符。旧版 .doc/.xls/.ppt 请先另存为新格式。
- **图片按模型能力处理**：设置页新增「当前模型支持图片输入（多模态）」，模型名含 vision / omni / gpt-4o 等字样时自动勾选。勾选后图片以标准 `image_url`（base64）内容发送；未勾选时图片仍保存在本机、在对话中可预览，但会明确告知模型“看不到图片内容”，不会假装读过。
- 每种格式都做扩展名与文件头双重校验（Office 必须是真 zip 且含对应部件、PDF 必须以 `%PDF-` 开头、图片必须匹配魔数），二进制伪装成文本会被拒绝；XML 解析使用 defusedxml，解压前检查成员大小，超大或损坏文件给出明确错误。
- 附件记录在对话历史中（可回看当时上传了什么），导出对话会带出附件名；`GET /chat/attachments` 可列出、`DELETE /chat/attachment` 可删除本机文件。AI 只能读取，不能修改或删除附件。
- 图片或扫描件没有文字层时不会伪造内容：工具会返回「没有可提取文字，不要编造」的提示。

Windows x64 MSI 可覆盖升级，保留数据库、凭据与已上传附件。本次产物：`releases/ScholarMate_0.7.0_x64_zh-CN.msi`、`releases/ScholarMate-source-0.7.0.zip`，校验值见 `releases/SHA256SUMS.txt`。安装包未签名。

## v0.5.0（2026-09-15）

- **引用不再需要人工替换**：打开「阅读 / 引用」即自动识别并生成 GB/T 7714-2015 顺序编码制条目。识别顺序为 PDF 首页/页脚 → DOI 精确查询 → Crossref、OpenAlex、Europe PMC、arXiv、DataCite 的精确标题匹配。外文作者统一转成国标写法（`EINSTEIN A`），超过三位作者按国标省略为 `et al.`。
- 无法确认的要素不再打印 `〔待补充〕`：条目按国标省略该要素（如期刊缺卷期时写作 `[J]. 刊名, 2026.`），并在界面单列说明省略了什么、依据来自哪里。没有任何来源信息时退化为 `[Z]` 而不是伪造网址。
- **文件名不再决定文献身份**：文件名为编号、`download`、`cnki_2026` 等无意义名称时，从 PDF 正文识别原标题、作者、年份与刊物；模型给出的每一个字段都要在 PDF 正文中逐字命中才会写入，否则丢弃，避免编造。
- **阅读改为沉浸式对照**：打开阅读 / 引用立即显示整篇 PDF（连续滚动、按需渲染、远处页面释放显存）。「翻译全文 · 中英对照」一次性逐页翻译，左侧原文、右侧同一页的译文覆盖在原文位置，排版、图表、公式与 PDF 文件本身都不改变。中文文献自动识别并提示无需翻译，可随时停止，已翻译页面不重复请求。浏览器插件的官方 PDF 服务需上传文件到第三方并申请 SDK，本版仍只提供官方入口，不嵌入该插件。
- **C 盘不再堆积副本**：导入只关联原文件；文献库新增「本地存储」面板，显示应用数据目录、应用下载目录以及其中实际占用的字节数。「检查重复副本」会按字节比对，列出应用数据目录里与你自己文件完全相同的副本，确认后一次性清理并改为关联原文件。清理范围严格限制在应用自己的旧导入目录，绝不扫描或删除其他文件。
- 引用新增 `citation_checked` 标记，同一篇文献不会重复联网识别；手动修改资料后仍以你填写的字段为准。

Windows x64 MSI 可覆盖升级，保留数据库和凭据。升级后旧版导入副本不会自动删除，请在文献库用「检查重复副本」清理。本次产物：`releases/ScholarMate_0.5.0_x64_zh-CN.msi`、`releases/ScholarMate-source-0.5.0.zip`，校验值见 `releases/SHA256SUMS.txt`。安装包未签名。

## 构建流程

1. 在目标系统安装 README 所列依赖，使用 Python 3.11 虚拟环境。
2. `npm ci` 安装锁定前端依赖，安装 Python requirements。
3. 运行 Python 测试、`npm test` 与 `npm run build`。
4. `npm run tauri icon scripts/icon.svg` 生成所有桌面图标。
5. 用虚拟环境 Python 执行 `scripts/build_sidecar.py`。脚本自动读取 Rust host triple，产生 externalBin 所需后缀文件。
6. Windows 执行 `npm run tauri build -- --bundles msi`；macOS 执行 `npm run tauri build -- --bundles dmg`。
7. 在干净设备上安装验证；检查启动、凭据存取、真实 AI、导出中文 PDF 和退出后的子进程清理。

提供了手动触发的 GitHub Actions Windows/macOS 构建工作流；未自动发布到任何外部平台。首次使用需将项目放入你自己的 GitHub 仓库。

## 签名与分发

当前构建配置生成未签名安装包。公开分发前为 Windows 配置代码签名证书，为 macOS 配置 Developer ID 签名和 notarization；证书/密码由 CI secrets 提供，不提交仓库。macOS sidecar 必须随应用签名、公证，并在实际设备检查 Keychain 授权。Windows 需核对 WebView2 安装策略和 SmartScreen 行为。

## 已知限制

- 只支持原生 Windows/macOS 凭据管理器；不支持 Linux 密钥存储。
- 未集成 OCR、向量库、RAG、翻译历史、任意第三方 Base URL、自动更新。
- PDF 导出采用基本排版，复杂数学公式/表格不保证还原。总结仅用节选，不能替代全文审读。
- 自动化测试使用模拟模型及网络，不消耗真实 API 额度。真实 Key、操作系统权限和安装包需要人工验收。
- 已提供 Windows Python 3.11 实测依赖锁定文件 `src-tauri/python/requirements-lock-windows.txt`。macOS 使用通用 requirements，并在目标平台验证、锁定依赖。
